# Release audit corrections — 22 September 2026

The owner supplied the audit; its findings are checked against the implementation rather than treated as performance measurements. This change preserves the selected adjacent compact passage/tab controls, the wide sidebar composition, the bundled Scripture, and existing user storage. It does not establish release acceptance.

## Implemented

- **1 — Privacy:** the app bundles its own `PrivacyInfo.xcprivacy`, declaring app-only UserDefaults access with CA92.1, no tracking, and no collected data. GRDB retains its separate manifest. Checked the manifest in an unsigned Release app and in a bundle regression test; no App Store submission was performed.
- **2 — Accessible turns:** Reduce Motion, Reduce Transparency, Increase Contrast, and VoiceOver choose immediate chapter transitions without disabling chapter swipe intent. VoiceOver comes from SwiftUI's live accessibility environment. Native previous/next controls remain available.
- **3 — Verse accessibility:** custom actions are prepared regardless of VoiceOver status. Accessibility frames lazily union the complete selection rectangles, including wrapped lines. Preparing the chapter's elements no longer requests every verse's layout rectangle. Observe VoiceOver/Switch Control status changes. A narrow text-view regression checks the final line and actions with VoiceOver off; assistive-input device review remains required.
- **4 — Localization:** native selection menus, tab destinations, chapter titles, colors, accessibility actions/status, errors, appearance/Saved options, and editorial book descriptions use extracted localization keys. Sync compiler `.stringsdata` into `Localizable.xcstrings`. Scripture, canonical IDs, source notices, and model instructions are not translated. This supplies English localization infrastructure, not additional language translations.
- **5 — Highlights:** strengthen ordinary fills and add light/dark high-contrast asset variants. Increased-contrast foreground variants preserve readable text on those fills. Tests cover all four colors in both appearances and contrast settings: text contrast at least 4.5:1, ordinary canvas distinction at least 1.5:1, high-contrast distinction at least 3:1. These are the chosen engineering thresholds, not a claim that every highlight is a standalone WCAG control.
- **6, 18 — Picker:** remove glass from chapter cells, keep plain circular selection/borders, use the native close role, and label Books with a book symbol rather than an imitation back chevron. Retain the owner's full-width numbers and explicit popover dismissal binding.
- **7 — Scheduling:** synchronous storage work runs on a retained DispatchSerialQueue actor executor instead of occupying the cooperative executor. Search already used GRDB's asynchronous read API; it now has a separate read-only connection, so an in-flight FTS query does not occupy the chapter connection. Serialized annotation transactions and cache ownership remain intact.
- **8, 9 — Saved/decoding:** resolve Saved from batched verse rows, with per-chapter ID indexes, without decoding chapter documents or evicting the reader cache. Chapter/position decoding reuse the decoder and fetch payload bytes. Existing annotation migration, exact quote verification, unresolved records, grouping, deletion, and conflict-safe Undo tests remain in force.
- **10, 11 — Repeated work:** batch observed highlight/bookmark mutations; cache flattened annotations and highlighted chapter IDs by revision; cache the filtered/sorted Saved presentation. Later pages reuse the matching immutable-corpus search count (and calculate it if no matching count is available).
- **13 — Resizing:** keep one NavigationSplitView and reader detail identity across the 920-point boundary. Hide compact back navigation so its interactive pop does not steal rightward chapter swipes. Only mount the detail Search field where used; keep shared Search state. Avoid replacing a settled semantic reading anchor with intermediate resize geometry.
- **14 — Summary:** stream the final overview/reduction into a labeled draft while generation and refusal review finish; cancellation/request identities reject late updates. Optional title/people decoration was already after the completed overview and remains nonblocking. Draft text remains distinct from Scripture and can disappear on refusal. Tests use synthetic content, not claims about model quality.
- **15 — Selection menu:** cache color swatches until appearance/contrast changes; check selection using a semantic attributed highlight-color ID instead of UIColor equality.
- **16, 17 — System integration:** connect session annotation Undo to the scene UndoManager and text view; retain explicit Undo and atomic conflict protection. Register search, chapter, and sidebar shortcuts in scene commands. A native UndoManager regression verifies persisted annotation removal. Physical keyboard, shake, and three-finger interaction remain device checks.
- **19, 20 — Chrome:** remove the duplicate wide About control. Passage text chooses full/abbreviated/fallback labels using ViewThatFits and actual space instead of book-name character counts. Owner-selected wide destination controls remain.
- **21 — Lifecycle:** acquire a finite UIKit background-task allowance before scheduling a position flush, release it on completion/expiration, and retain Complete file protection and visible write errors. This improves the opportunity to save; it cannot guarantee a protected write after lock.
- **Hygiene:** centralize verse-to-chapter identity extraction. Allocate a neighboring page's preview ReaderState lazily; it remains bounded by the existing neighboring-page cache.

## Deliberately outstanding

- **7 (WAL/pool):** retain the current user DatabaseQueue/journal mode. A pool/WAL switch changes sidecar, backup, lock/protection, and cross-connection behavior; evaluate it with measured position-save latency and migration/lock tests. Changing journal mode alone is not evidence of faster or safer persistence.
- **9, 12 (corpus format/indexes):** binary chapter payloads, external-content FTS, and redundant-index removal require importer changes, regeneration/checksum review, search/integrity tests, and size/latency measurements. No shipping corpus or source manifest was altered in this UI/accessibility pass.
- **14 (prewarming):** do not create a throwaway prewarm session immediately before generating. Apple's guidance calls for at least one second of lead time; any future approach should retain and reuse the same session and measure memory/latency. On-device model quality/refusal/streaming latency are not simulator evidence.
- **19, 22 (advisory):** retain the owner-approved sidebar controls, single active scene, and Search composition. Native TabView/sidebarAdaptable, multiple windows, and searchable would be separate product/layout decisions.
- Full VoiceOver/Switch Control/Voice Control, reduced-motion/transparency settings, keyboard overlays, background/lock timing, physical-device performance, provenance/rights, offline network capture, signing, and App Store review remain release gates.

# 0002 — Native reader risk prototypes

Status: native prototype implemented; simulator checks recorded below, 21 September 2026.

## Scope and source authority

This milestone proves renderer and navigation risks. It is a Debug-only development reader, not a release Bible. The pinned eBible.org USFX archive is in `Content/Source/`; `prototype-manifest.json` records its SHA-256 and conversion policy. John 2–4 and Psalm 119 are complete source-derived chapters, not text transcribed from the HTML mock or generated by AI. Source rights/territories and final canon remain unresolved.

`Content/Tools/make_prototype_fixtures.py` is deliberately narrow. It preserves wording, punctuation, added-word italics, source headings/notes, and paragraph/poetry metadata. It collapses XML formatting whitespace and does not render lexical annotations. It rejects unknown markers inside selected chapters and DTD/entity declarations. This does not replace the release importer, schema, corpus audit, or provenance review in milestone 3.

## Renderer

Use one UITextView per chapter with explicitly connected `NSTextContentStorage`, `NSTextLayoutManager`, and `NSTextContainer`, retaining TextKit 2. The inherited convenience initializer bypassed Swift subclass property initialization in the first runtime trial; explicit construction fixes that crash. Never access its legacy `layoutManager`. The semantic text map relates UTF-16 ranges to stable fixture verse IDs; composed-character clamping protects revised anchors. Header labels and layout-derived gutter numbers are separate native views, not selectable text.

Native selection and edit menus provide touch handles. Copy formats the exact selection plus reference/edition and marks partial excerpts. A custom menu opens whole-verse highlight/bookmark controls; sharing uses the system sheet. Highlight background attributes update in place rather than replacing the chapter. Colors, bookmarks, selection, and reading anchors are session-only: no durability is claimed.

The native scrolling viewport extends behind navigation and floating bottom glass controls. Measured SwiftUI safe-area clearances become internal heading/final-verse padding, rather than clipping the viewport. Only vertical edges extend; split-view horizontal boundaries remain intact. The heading begins below the toolbar and moves underneath it when scrolled.

The scrolling header is aligned with the verse column. TextKit layout fragments place gutter numbers at the first baseline. The text container stays bounded to the reference width, and fonts use system serif/sans with scaled metrics. Psalm headings/notes remain in the fixture model but their display is deferred; this is not a final semantic content renderer.

## Navigation

The Debug launch argument `--native-tabs-probe` renders the actual native `TabView`/`.sidebarAdaptable`/bottom-accessory alternative for comparison. On iOS 27 the native comparison rendered the accessory above a full-width tab bar, rather than beside labeled destinations. For the selected 2a composition, the compact container therefore places the passage capsule beside three labeled destination buttons with public glass APIs. It changes to two rows at accessibility sizes or when content does not fit.

The wide layout uses native `NavigationSplitView` with a 320-point sidebar and toolbar passage control. A 920-point usable-container threshold reserves room for the sidebar and a legible column; it is an engineering starting point, not a device-model rule. The reader owns selection/position separately from its container so switching layouts and destinations can restore semantic anchors.

The chapter picker exposes only the four actual development fixtures. It exercises native popover-to-sheet adaptation and circular current selection; it is not the complete 2b book/chapter/reference navigator. Search is explicitly unavailable. Saved is a session-annotation inspection surface, not final grouped range persistence. Release configuration excludes `PrototypeChapters.json` and routes to the missing-content screen.

## Remaining work after this prototype

Production content/schema, notes and poetry rendering, persisted reading position and annotations, transactional range bookmarks/Undo, full picker and search, and final device/accessibility/performance acceptance remain separate milestones. Do not treat simulator success as physical-device or VoiceOver sign-off.

- iPad mini (A17 Pro), iPadOS 26: seven Swift Testing cases, native annotation menu, chapter/theme round trip, missing-content handling, and wide/narrow restoration pass (`.build/Prototype-iPad-2.xcresult`). Its cross-verse drag initially stopped within verse 1; moving the gesture endpoint farther into verse 2 resolves the test. The focused rerun is `.build/Prototype-iPad-4.xcresult`. The compact native-tab comparison is intentionally iPhone-only.
- Two offline Python fixture tests pass. Debug/Release builds succeed; Release app inspection confirms no `PrototypeChapters.json`. No Swift compiler warnings were introduced (Xcode emits its App Intents metadata-skipped notice).
- Initial and scrolled compact screenshots confirm content extends behind glass and the initial heading clears the toolbar. Wide-layout automated screenshots have a simulator rotation/cropping artifact, so they are not final visual acceptance evidence. Freeform window resizing and physical-device inspection remain open.
- All six preserved design-source files still match their recorded SHA-256 hashes.

Accessibility metadata/order/actions are unit-tested, but actual VoiceOver speech and navigation, the full Dynamic Type matrix, keyboard/pointer workflows, and real-device performance require further checks. These are prototype limits, not release acceptance.
